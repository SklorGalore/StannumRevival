---
title: N-1-1 with system adjustment
description: How Stannum runs N-1-1 studies, with the first outage in AC, a redispatch as the system adjustment, then a contingency run from the adjusted case.
---

An N-1-1 run is a loop over first outages. For each one:

1. **First outage.** The element goes out as in a
   [contingency run](/StannumRevival/manual/contingencies/): branches and
   generators offline, split-off buses isolated, lost generation shared as
   the run's **pickup** setting says, and a new reference bus if the old one
   lost its last unit. The case is solved in AC from the base solution with
   every control of the last solve. When the solve fails, the first outage
   is reported as not solving and no pairs follow it.
2. **System adjustment.** With **Redispatch**, the
   [redispatch](/StannumRevival/manual/redispatch/) works on the solved
   post-outage case: a DC optimal power flow that moves generation as little
   as possible within each island, checked with AC passes, until every
   monitored branch is within the limit or no unit can help. Its last
   converged AC solve is the adjusted case. A switched shunt in voltage
   control that the first outage took out stays out.
3. **Second outages.** A contingency run over the adjusted case, with the
   run's settings: every outage in AC when there are at most 2,000, otherwise
   the linear screen from the adjusted case's factors and the worst in AC.
   Overloads and voltage problems are new or worse against the adjusted
   case, so what the adjustment couldn't fix is reported only when the
   second outage worsens it by more than the **worse by** threshold.

The first outage is out during the second run, so it is not taken out
again: with both lists the same, `n` outages give `n·(n−1)` pairs, each in
both orders, since the adjustment after `A` differs from the one after
`B`.

## Ranking

Pairs are ranked as contingency rows are: AC results ahead of screened
ones, then by severity (the worst new or worse loading over the limit, or a
voltage problem on the same scale; a failed solve is infinitely bad). The
run keeps the worst `keep_pairs` (2,000 by default) and counts every pair.

First outages are listed with those that don't solve first, then by how
many second outages found a problem, then by the worst severity among the
pairs that solved.

## Cost

Each first outage costs one AC solve, the redispatch's linear programs and
AC passes, and a full contingency run. A 200-bus case with 310 elements
(95,450 pairs, all in AC) took about 80 seconds on four cores; list the
first outages to keep a big case's run short.
